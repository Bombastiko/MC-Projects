Documentation

FuseBox system references and API documentation.

Quick Start: Stopwatches (sw)

Stopwatches are created and immediately active. Use them to track elapsed time.

1. Reload Minecraft datapacks:

/reload

2. Create and run a stopwatch:

/function fb:sw/create {name:"demo"}

3. Register player display layout:

/function fb:sw/display_ab_custom {player:"@a",sw:"demo",format:"digital_short",color:"gold",color_sec:"yellow",color_num:"white",prefix:"Time: ",suffix:"",bold:"false",global_type:"soft"}

Quick Start: Countdown Timers (cd)

Countdowns initialize in a paused state. You must explicitly start them to begin ticking down.

1. Initialize a countdown (1 minute, 30 seconds):

/function fb:cd/create {name:"my_timer",h:0,m:1,s:30,on_complete:"say Done!",animation:"flash"}

2. Assign display config to players:

/function fb:cd/display_ab_custom {player:"@a",cd:"my_timer",format:"digital_short",color:"red",color_sec:"yellow",color_num:"white",prefix:"Time Left: ",suffix:"",bold:"false",global_type:"soft"}

3. Start the timer:

/function fb:cd/start {name:"my_timer"}

Controlling Active Timers

Manage stopwatch and countdown states dynamically using player-executable commands.

Action Stopwatch Command Countdown Command Effect
Start (Automatic) /function fb:cd/start {name:"x"} Registers timer to the active ticking loops.
Pause /function fb:sw/pause {name:"x"} /function fb:cd/pause {name:"x"} Suspends tick decrementing. Renders ausgegraut & italic.
Resume /function fb:sw/resume {name:"x"} /function fb:cd/resume {name:"x"} Restores active ticking state and default colors.
Delete /function fb:sw/delete {name:"x"} /function fb:cd/delete {name:"x"} Wipes NBT config, registers, and resets objectives.

Timer Database Storage Paths (for NBT manipulation):

  • Stopwatches: fb:main sw.list (Running names)
  • Countdowns Running List: fb:main cd.list (Ticking timers)
  • Countdowns Static Registry: fb:main cd.db (Configuration & Commands)

Display Priority Rules

Display configurations determine what is printed to the actionbar. Priorities resolve conflicts when multiple layouts are configured.

1. Global configuration (targetting @a):

  • soft: Default global display. Overridden automatically if a player receives an individual layout.
  • hard: Enforces global layouts. Bypasses individual configurations for all players.

2. Individual configuration (targetting specific usernames):

Bypasses soft global displays for that specific player. Useful for map cutscenes or player-specific race timers.

3. Clear actionbar display settings:

Removes a player's registry and resets their custom settings, defaulting them back to global configuration:

/function fb:display/ab/clear {player:"oneBombastiko"}

Event System API

Register callback functions or direct commands that trigger automatically upon gameplay events. Callbacks are invoked as the player who triggered the event, with macro parameters containing the player username in $(player).

Standard Events

  • onJoin: Fires when a player logs in or joins the world.
  • onDeath: Fires immediately when a player dies.
  • onLeave: Fires immediately when a player disconnects or leaves.
  • onKillPlayer: Fires as the killer when they kill another player.
  • onKilledByPlayer: Fires as the victim when killed by another player.

Item-Specific Events

  • onRightClick: Fires when a player right-clicks holding a Carrot on a Stick or Warped Fungus on a Stick.
  • onHoldItem: Fires every tick while a player is holding a specific item.

API Registration Commands

1. Function Callbacks (Standard Events):

/function fb:event/register {event:"onJoin", fn:"my_pack:welcome"}

2. Direct Command Callbacks (Standard Events):

Executes a direct command immediately. Use @s to target the event player.

/function fb:event/register_cmd {event:"onJoin", cmd:"say Welcome back, @s!"}

3. Function Callbacks (Item Events):

Only fires if the held item matches the specified ID and custom NBT data compound.

/function fb:event/register_item {event:"onRightClick", fn:"my_pack:cast_spell", item_id:"minecraft:carrot_on_a_stick", custom_data:{wand_type:"fire"}}

4. Direct Command Callbacks (Item Events):

/function fb:event/register_item_cmd {event:"onRightClick", cmd:"effect give @s speed 5 1", item_id:"minecraft:carrot_on_a_stick", custom_data:{wand_type:"speed"}}

API Unregistration & Cleaning

To unregister, use the corresponding unregister commands. Pass the exact filters (item_id, custom_data) used during registration to target specific items:

  • Unregister Standard Function: 
    /function fb:event/unregister {event:"onJoin", fn:"my_pack:welcome"}
  • Unregister Standard Command: 
    /function fb:event/unregister_cmd {event:"onJoin", cmd:"say Welcome back, @s!"}
  • Unregister Item Function: 
    /function fb:event/unregister_item {event:"onRightClick", fn:"my_pack:cast_spell", item_id:"minecraft:carrot_on_a_stick", custom_data:{wand_type:"fire"}}
  • Unregister Item Command: 
    /function fb:event/unregister_item_cmd {event:"onRightClick", cmd:"effect give @s speed 5 1", item_id:"minecraft:carrot_on_a_stick", custom_data:{wand_type:"speed"}}
  • Clear All Callbacks for Event: 
    /function fb:event/clear {event:"onJoin"}

Custom Items & Custom Data (1.20.5+)

In modern Minecraft, custom items are uniquely identified by tags in their minecraft:custom_data component. For example, a custom fire staff item can be generated with:

/give @s carrot_on_a_stick[custom_data={wand_type:"fire"}]

Datapack Dependency Check

If you are developing a custom datapack that requires FuseBox, you can include a simple check in your pack's load function to verify if FuseBox is installed and up-to-date.

Copy-Paste Integration:

Add these commands to the end of your datapack's load.mcfunction (replace my_pack with your pack's namespace):

# 1. Initialize temporary check objective
scoreboard objectives add fb.version dummy
scoreboard players set #fb_installed fb.version 0

# 2. Call FuseBox version check function
# (If FuseBox is installed, this function sets #fb_installed fb.version to the version number)
function fb:api/check_version

# 3. Check results and display errors/warnings
# (If score is still 0, FuseBox is NOT installed or has been removed)
execute if score #fb_installed fb.version matches 0 run tellraw @a [{"text": "[my_pack] ", "color": "gold", "bold": true}, {"text": "Error: FuseBox is NOT installed! This pack requires FuseBox v0.1 Alpha or newer.", "color": "red"}]

# (If score is less than the required version (e.g., 1 for v0.1), warn the user)
execute if score #fb_installed fb.version matches 1.. if score #fb_installed fb.version matches ..0 run tellraw @a [{"text": "[my_pack] ", "color": "gold", "bold": true}, {"text": "Warning: FuseBox is out of date! Please update FuseBox to at least v0.1 Alpha.", "color": "red"}]

Debugging & Administration

FuseBox features built-in tools to inspect NBT storages, check active objectives, and safely clear data.

1. Toggle Debug Mode:

Prints internal processing status and ticking updates directly in the chat.

# Turn debug ON
/data modify storage fb:config debug set value 1b

# Turn debug OFF
/data modify storage fb:config debug set value 0b

2. Print Scoreboard and Registry Dumps:

Outputs formatted listings of all running timers, event registrations, and objective values to chat.

# Inspect stopwatches
/function fb:sw/debug_info

# Inspect countdowns
/function fb:cd/debug_info

# Inspect event registrations
/function fb:event/debug_info

3. Wipe Storages:

Safely resets databases to clean up or troubleshoot errors.

# Reset Stopwatch data
/function fb:sw/reset-db

# Reset Countdown data
/function fb:cd/reset-db
